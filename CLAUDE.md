## Project state

This is Ismail Kayadelen's personal portfolio site. The `app/` directory is currently still the
unmodified `create-next-app` boilerplate (single route, placeholder copy/logo) — the real site has
not been built yet. The actual design language to build toward lives in
`ismail-portfolio-design-system/` (see below), not in `app/`.

## Commands

- `npm run dev` — start the dev server (Turbopack, per Next.js 16 default)
- `npm run build` — production build
- `npm run start` — serve the production build
- `npm run lint` — ESLint via `eslint-config-next` (flat config in `eslint.config.mjs`)

There is no test runner configured in this repo.

## Next.js 16 caveat

This repo pins `next@16.3.2`, a version newer than most training data. The AGENTS.md import above
(auto-regenerated by `next dev` — don't hand-edit its content) is the standing reminder to check
`node_modules/next/dist/docs/` for current App Router APIs before assuming Next 13/14-era patterns
(e.g. route conventions, config options, data fetching) still apply.

## Architecture

- **App Router only**, TypeScript, no `src/` dir — routes live directly under `app/`. Path alias
  `@/*` resolves to the repo root (`tsconfig.json`).
- **Styling is Tailwind v4**, imported via `@import "tailwindcss"` in `app/globals.css` — there is
  no `tailwind.config.js`; theme tokens are declared inline with `@theme inline { ... }` in that
  same CSS file (CSS-first config, per Tailwind v4).
- **Fonts** are loaded via `next/font/google` in `app/layout.tsx` (currently Geist/Geist Mono from
  the boilerplate — expected to be swapped for the design system's fonts once the real UI lands).

## Design system (`ismail-portfolio-design-system/`)

This directory is the source of design truth for the site and is *not yet wired into* `app/`. It's
packaged as a Claude Agent Skill (`SKILL.md`, user-invocable as `ismail-design`) documenting a
monochrome editorial visual language distilled from a reference template, adapted for Ismail
Kayadelen's brand. Read `ismail-portfolio-design-system/readme.md` in full before implementing UI —
it's the canonical spec (voice/copy rules, color/type/spacing/motion tokens, component inventory,
icon rules). Key points to know going in:

- **Visual language**: black-on-white, oversized display grotesque headlines (ALL CAPS) paired with
  uppercase tracked monospace for every label/meta/number. Square corners everywhere (all radius
  tokens resolve to 0). Color comes from photography, not UI — three accent colors exist but are
  rationed to link/focus/selection states only.
- **`tokens/*.css`** — CSS custom properties for colors, typography, spacing, motion, fonts;
  `styles.css` is the aggregating entry point. Fonts are substitutes (Archivo, JetBrains Mono via
  Google Fonts) standing in for unavailable licensed webfonts — swap only `tokens/fonts.css` if real
  font files arrive.
- **`components/*`** — plain `.jsx` (+ `.d.ts` + `.prompt.md` per component), organized into
  `core/`, `brand/`, `navigation/`, `content/`, `forms/`. These are reference implementations, not
  Next.js-integrated — porting one into `app/` means converting to `.tsx` and adapting to App Router
  conventions (Server/Client Component boundaries, `next/image`, etc.).
- **`ui_kits/portfolio/`** — a full click-through static prototype of the site (home/about/work
  index/case study/contact) as plain HTML+JSX+`data.js`. Use this as the layout/flow reference when
  building the real routes.
- **`guidelines/*.card.html`** — visual spec sheets (one per foundation: colors, type, spacing,
  brand) for checking a value against the system at a glance.
- Icons: a fixed 12-glyph Lucide subset only (see readme's ICONOGRAPHY section) — no other icon
  library, no emoji as UI icons.
